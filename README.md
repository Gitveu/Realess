# realess-t300 🎧

Автономное Android-приложение (**BudsT300Controller**, Kotlin + Jetpack Compose) и завершённое реверс-инжиниринговое исследование протокола для прямого управления наушниками **Realme Buds T300** — без realme Link, напрямую по Bluetooth.

**Статус:** реверс-инжиниринг протокола завершён. Все команды и форматы кадров подтверждены экспериментально на физических Buds T300; приложение разработано и собрано.

Исходный артефакт анализа: `realme Link.apkm` (пакет `com.realme.link`, стек TL TWS `com.realme.iot.headset.tl.*`).

---

## 🎯 Назначение

Проект решает две задачи:

1. **Документация протокола** обмена Realme Buds T300 — кадровый формат, транспорт, полный набор команд и асинхронных событий.
2. **Автономное приложение**, работающее с наушниками напрямую, без облака и без приложения производителя:
   - точное чтение заряда левого наушника, правого наушника и кейса с учётом статуса зарядки;
   - управление и мгновенное чтение режимов ANC;
   - переключение и чтение Game Mode;
   - чтение и переключение пресетов эквалайзера, распознавание пользовательских профилей;
   - чтение и настройка действий сенсорных кнопок для обоих наушников;
   - управление и чтение пространственного аудио с локальным демо-воспроизведением оригинальных сэмплов;
   - подписка на асинхронные события наушников.

## 🚀 Возможности приложения

### Автоподключение Zero-Touch
Никаких кнопок выбора и диалогов поиска. Приложение регистрирует системный `BroadcastReceiver` на `ACTION_ACL_CONNECTED`, `ACTION_ACL_DISCONNECTED`, `ACTION_CONNECTION_STATE_CHANGED`. При извлечении наушников из кейса телефон поднимает профиль A2DP, а приложение автоматически открывает канал управления. При помещении обоих наушников в кейс статус переходит в `In case / disconnected`.

### Заряд батареи (L / Case / R)
- Точный процент (0–100%) для левого, правого наушника и кейса, индикатор зарядки `⚡`.
- Корректная обработка закрытого кейса: прошивка присылает `03 00` как оффлайн-маркер — парсер нормализует его в `-1`, UI показывает «—», неактивный слот не попадает в лог.
- Автоактуализация по событиям открытия/закрытия кейса и извлечения второго наушника (дебаунс 400 мс), фоновый опрос каждые 8 секунд.

### Шумоподавление (ANC)
Мгновенное переключение и чтение трёх режимов: 🛡️ **Шумоподавление**, ⭕ **Выкл.**, 🔊 **Прозрачность**.

### Игровой режим (Game Mode)
Переключение и чтение состояния минимальной задержки, синхронизация с аппаратной ножкой наушников через события.

### Эквалайзер
Пресеты **Серенада**, **Оригинальный звук**, **Чистые басы**, **Глубокие басы**; распознавание активного пользовательского профиля по имени через команду `0x0122` с подсветкой плашки в UI.

### Сенсорные жесты
Чтение и настройка действий на двойное касание, тройное касание и удержание отдельно для левого и правого наушника, с фильтрацией допустимых функций под каждый жест.

### Пространственное аудио (Spatial Audio / 3D Sound)
Управление и чтение режима. Демо-воспроизведение — локальная функция смартфона через `MediaPlayer`, а не команда в наушники; интегрированы оригинальные треки `headset_spatial_audio_fix.mp3` (3D) и `headset_spatial_audio_off.m4a` (стерео) с переключением на лету.

### Live-консоль протокола
Сворачиваемая панель логов с входящими и исходящими кадрами в реальном времени.

## 🔬 Транспорт

### Bluetooth Classic RFCOMM SPP (основной)
Наушники сопрягаются как стандартная гарнитура (A2DP / HFP), канал управления — RFCOMM SPP:

- Основной вендорный UUID realme / OPPO / OnePlus: `0000079A-D102-11E1-9B23-00025B00A5A5`
- Стандартный SPP UUID (fallback): `00001101-0000-1000-8000-00805F9B34FB`
- Резервные вендорные UUID: `db764ac8-4b08-7f25-aafe-59d03c27bae4`, `db764ac8-4b08-7f25-aafe-59d03c27bae3`

```kotlin
device.createRfcommSocketToServiceRecord(REALME_VENDOR_SPP_UUID)
```

Чтение и запись — напрямую через `socket.inputStream` / `socket.outputStream`.

### BLE GATT (резервный)
При недоступности SPP-сокета — переход на GATT с автодетектом каналов записи (`PROPERTY_WRITE` / `PROPERTY_WRITE_NO_RESPONSE`) и уведомлений (`PROPERTY_NOTIFY`, CCCD `00002902-0000-1000-8000-00805f9b34fb`).

## 🧩 Формат кадров (Wire Frames)

Двухуровневая инкапсуляция: внутренний TL-кадр всегда оборачивается в транспортный фрейм OPPOv1.

### Транспортное обрамление OPPOv1 (SOF `0xAA`)
| Смещение | Поле |
|---|---|
| 0 | `0xAA` — Start of Frame |
| 1..K | Длина пакета (varint 7-bit, = `TL_FRAME_LENGTH + 2`); для пакетов < 128 байт — 1 байт |
| K+1 | Флаги (`0x00` — одиночный пакет) |
| K+2 | Резерв (`0x00`) |
| K+3.. | Внутренний TL-кадр |

### Внутренний TL-кадр
| Смещение | Поле |
|---|---|
| 0..1 | Command ID (little-endian) |
| 2 | Device Address (`0x00`) |
| 3..4 | Payload Length (little-endian) |
| 5..N | Payload |

## 📡 Справочник протокола

Все кадры идут через RFCOMM SPP в обёртке OPPOv1.

| Функция | TX Cmd | TX Payload | RX Cmd | RX Payload |
|---|:---:|---|:---:|---|
| Запрос батареи | `0x0106` | — | `0x8106` | `[00, count, (slot, level\|flag)...]` |
| Установка ANC | `0x0404` | `01 01 <mode>` | `0x8404` | `[00]` |
| Запрос режима ANC | `0x010C` | `01 01` | `0x810C` | `[00, 01, 01, <mode>]` |
| Запрос Game Mode | `0x010D` | `01 06` | `0x810D` | `[00, count, (06, val)...]` |
| Установка Game Mode | `0x0403` | `06 <01/00>` | `0x8403` | `[00]` |
| Запрос Spatial Audio | `0x010D` | `01 1B` | `0x810D` | `[00, count, (1B, val)...]` |
| Установка Spatial Audio | `0x0403` | `1B <01/00>` | `0x8403` | `[00]` |
| Запрос пресета EQ | `0x010F` | — | `0x810F` | `[00, <eqId>]` |
| Установка пресета EQ | `0x0406` | `<eqId>` | `0x8406` | `[00]` |
| Запрос кастомных EQ | `0x0122` | — | `0x8122` | `[00, count, (selected, …, name)...]` |
| Запрос настроек кнопок | `0x0108` | `0E 01 03 04 … 00` | `0x8108` | `[00, count, (dev, 1, act, func)...]` |
| Установка настройки кнопки | `0x0401` | `01 dev 01 act func` | `0x8401` | `[00]` |
| Подписка на события | `0x0201` | `<eventType>` | `0x8201` | `[00]` |
| Асинхронные события | — | — | `0x0204` | `[03, …]`, `[05, val]` |

**Ключевые значения:**

- `noiseStatus`: `0x08` ANC / `0x01` Выкл. / `0x02` Прозрачность
- `componentId`: `0x01` левый / `0x02` правый / `0x03` кейс; `value & 0x7F` — уровень, `value & 0x80` — признак зарядки
- `eqId`: `0x02` Серенада / `0x00` Оригинальный / `0x03` Чистые басы / `0x01` Глубокие басы / `> 0x03`, `0xFF` — пользовательский
- `actionId`: `0x02` двойное касание / `0x03` тройное / `0x04` удержание 1 с
- `eventType`: `0x03` ANC / `0x05` Game Mode / `0x01` батарея / `0x02` статус в ухе-в кейсе

**Примеры полных кадров:**

```
Запрос батареи:      AA 07 00 00 06 01 00 00 00
ANC ON:              AA 0A 00 00 04 04 00 03 00 01 01 08
ANC OFF:             AA 0A 00 00 04 04 00 03 00 01 01 01
Прозрачность:        AA 0A 00 00 04 04 00 03 00 01 01 02
Game Mode ON:        AA 07 00 00 03 04 00 02 00 06 01
Spatial Audio ON:    AA 07 00 00 03 04 00 02 00 1B 01
```

Прочие входящие события инициируют безопасный отложенный опрос полного снимка состояния через `scheduleStateRefresh(120 ms)`.

Полный отчёт и дизассемблерный анализ — в [AGENTS.md](AGENTS.md).

### Технологический стек
Kotlin, Jetpack Compose (Material3), Coroutines / Flow, MinSdk 26, TargetSdk 34.

### Локализация
Английский по умолчанию (`values/strings.xml`), полная русская локализация (`values-ru/strings.xml`), выбор языка приложения в Android 13+ (`res/xml/locales_config.xml`, `android:localeConfig`). Технические логи протокола — на английском.

### Иконка
Адаптивная: повернутый на 90° по часовой стрелке символ realme Link с диагональной линией `/` и тёмной полупрозрачной обводкой в безопасной зоне 66 dp; градиентный векторный фон `#B662FE` → `#4F7FFF`, монохромный слой для тематических иконок Android 13+, legacy mipmap-ресурсы.

## 📲 Установка

1. Скачайте [BudsT300Controller-debug.apk](BudsT300Controller-debug.apk) и установите на Android 8.0+.
2. Выдайте разрешение «Устройства поблизости» (`BLUETOOTH_CONNECT`).
3. Приложение автоматически подхватит подключённые Buds T300.

### Сборка из исходников
```bash
git clone https://github.com/Gitveu/realess-t300.git
cd realess-t300/BudsT300Controller
./gradlew assembleDebug
```

Репозиторий: [github.com/Gitveu/realess-t300](https://github.com/Gitveu/realess-t300) (ветка `main`).
